# Upgrade async-snmp from 0.18 to 0.19

Set your `async-snmp` dependency to `"0.19"` in `Cargo.toml` and keep the feature
flags your application uses. If you use `Client::builder().connect()` or
`connect_tcp()` for queries, walks, SETs, or outgoing notifications, keep the same
setup and calls. If you inspect response metadata or match error variants,
update those calls. For the full list of changes, see the
[changelog](../../CHANGELOG.md).

## Read response diagnostics

- Replace the `ResponseMetadata::decode_anomalies` field with the
  `decode_anomalies()` iterator. Use `received_messages` when you need the
  original length, receive metadata, or anomalies for each accepted message.
- If you match on errors, use `error.kind()` to classify the failure or match on
  `error.exchange_source()` to access the underlying variant. After a later
  failure, read any retained discovery Reports or batch responses with
  `error.response_metadata()` on the original error.
- If you destructure `Error::ResponseShape`, its `response` is now boxed.

## Update shared UDP clients

In 0.18, create a shared transport with `UdpTransport::bind()`.

```rust,ignore
let shared = UdpTransport::bind("0.0.0.0:0").await?;
let client = Client::builder(target, Auth::v2c("public"))
    .build_with(&shared)
    .await?;
```

In 0.19, start the endpoint with `UdpEndpoint::spawn()` and keep the running
owner for as long as clients use the socket. Dropping the owner requests
shutdown for the shared endpoint and all its clients. If you configure the
endpoint with a builder, use `UdpEndpoint::builder()` and replace `build()`
with `spawn()`.

```rust
use async_snmp::{Auth, Client, UdpEndpoint, oid};

async fn poll(target: &str) -> async_snmp::Result<()> {
    let shared = UdpEndpoint::spawn("0.0.0.0:0").await?;
    let client = Client::builder(target, Auth::v2c("public"))
        .build_with(&shared)
        .await?;
    client.get(&oid!(1, 3, 6, 1, 2, 1, 1, 1, 0)).await?;
    shared.shutdown().await
}
```

### Use your own UDP socket and supervise the runner

Register the socket on the Tokio runtime that will service its I/O. During
setup, call `prepare()` and build your clients. During start, spawn the runner
and keep its `JoinHandle`. Keep the socket's I/O runtime running through shutdown.

```rust
use async_snmp::{Auth, Client, UdpEndpoint, oid};
use std::net::{SocketAddr, UdpSocket as StdUdpSocket};
use tokio::{net::UdpSocket, runtime::Handle};

async fn poll_on(
    runtime: &Handle,
    bind_addr: SocketAddr,
    target: &str,
) -> Result<(), Box<dyn std::error::Error>> {
    let socket = StdUdpSocket::bind(bind_addr)?;
    socket.set_nonblocking(true)?;
    let socket = {
        let _entered = runtime.enter();
        UdpSocket::from_std(socket)?
    };
    let (endpoint, runner) = UdpEndpoint::builder()
        .from_socket(socket)
        .prepare()
        .await?
        .into_parts();
    let client = Client::builder(target, Auth::v2c("public"))
        .build_with(&endpoint)
        .await?;
    let control = endpoint.control();

    let task = runtime.spawn(runner.run());
    let result = client.get(&oid!(1, 3, 6, 1, 2, 1, 1, 1, 0)).await;

    control.request_shutdown();
    task.await??;
    result?;
    Ok(())
}
```

Start the runner before issuing requests. Requests made before startup use their
normal timeout and retry budget. If setup is abandoned, drop the runner to close
the endpoint.

## Start and stop an agent

If you enable the `agent` feature, update how you start and stop the configured
agent. In 0.18, build the agent and run it directly.

```rust,ignore
let agent = builder.build().await?;
agent.run().await?;
```

In 0.19, spawn the configured agent and retain its running owner. Call `join()`
to wait for it to finish or `shutdown()` to request shutdown and join it.

```rust
use async_snmp::AgentBuilder;

async fn serve(builder: AgentBuilder) -> async_snmp::Result<()> {
    let running = builder.spawn().await?;
    for endpoint in running.bound_addresses() {
        println!("Bound on {}", endpoint.local_addr);
    }
    running.join().await
}
```

If your supervisor drives the agent, call `prepare().await?.into_parts()` and
run `runner.run()` in the supervisor. The tuple contains the agent, its
single-use runner, and an optional notification receiver. Keep your existing
handlers and access configuration. For `max_concurrent_requests(Some(n))`, pass
`n` directly. If you used `None` for unbounded concurrency, choose a positive
limit or use the default of 1,000. When UDP admission fills, the agent drops new
requests and counts the drops. Use `bound_addresses()` in place of `local_addr()`.

In 0.18, a command-only agent acknowledged valid Informs and discarded their
payload. In 0.19, a command-only agent ignores Informs by default. To keep the
old behavior, set `discard_notifications()`. To deliver notifications on the
command listeners, attach a `NotificationReceiver::builder()` with
`AgentBuilder::notifications()`. If the agent uses User-based Security Model
(USM) credentials, set an explicit `admission_policy()` on the attached receiver.
With `spawn()`, take the single consumer using `take_notifications()`.
[Shared UDP roles example](../../examples/shared_udp_roles.rs)

## Receive and acknowledge notifications

In 0.18, `recv()` takes `&self` and returns a `Result`.

```rust,ignore
let receiver = NotificationReceiver::bind("127.0.0.1:1162").await?;
loop {
    let event = receiver.recv().await?;
    println!("Notification from {}", event.source);
}
```

In 0.19, use `spawn()` for a standalone receiver with one mutable consumer. If
you configure a receiver with a builder, keep its `bind()` setting and replace
`build()` with `spawn()`. Read listener addresses with `bound_addresses()`. When
`recv()` returns `None`, use `join()` to check the runner's terminal result. To
stop a running receiver, call `shutdown()`. To request shutdown from another
task, pass it a `NotificationControl` from `receiver.control()`. If your loop
handled pre-acceptance persistence errors from `recv()`, read the receiver
control's `health()` or watch for changes with `subscribe_health()`.

```rust
use async_snmp::NotificationReceiver;

async fn receive() -> async_snmp::Result<()> {
    let mut receiver = NotificationReceiver::spawn("127.0.0.1:1162").await?;
    while let Some(event) = receiver.recv().await {
        println!("Notification from {}", event.receive_info.peer_addr());
    }
    receiver.join().await
}
```

- Replace `acceptance_policy()` or `try_acceptance_policy()` with
  `admission_policy()` or `try_admission_policy()`. The policy receives
  `NotificationAdmissionInfo` with the trap OID, receive metadata, and wire
  security fields. Replace `NotificationAcceptance::Accept` with
  `NotificationAdmissionDecision::Admit`, and use `Reject` on the new enum.
  Replace `accept_all_notifications()` with `admit_all_notifications()`. Inspect
  the notification payload after delivery.
- Match `NotificationAcknowledgement::Completed(outcome)` where you used
  `Some(outcome)` on `inform_ack`. Traps now report `NotRequired`. In the default
  automatic mode, the receiver attempts to acknowledge an accepted Inform before
  delivery.
- If you used the payload to decide whether to acknowledge, select
  `InformAcknowledgementMode::ApplicationControlled`. Inspect or persist the
  delivered payload. Match `NotificationAcknowledgement::Pending(token)` and
  call `token.acknowledge().await` or `token.reject()`. Complete admitted tokens
  before their deadlines and before shutting down the runner. This mode governs
  the ordinary response for delivered Informs. The receiver can send USM Reports
  and pre-delivery `tooBig` responses under either mode.
  [Durable acknowledgement example](../../examples/notification_durable.rs)

## Select a route for outgoing notifications

Replace `trap_sink(id, destination, auth)` with
`notification_sink(id, target, auth)`. Choose the `NotificationTarget` based on
the source port your collector expects. In 0.18, traps used the agent's UDP
listener and Informs used a separate UDP socket. In 0.19,
both operations use the same route for a given sink. With the default UDP bind,
`NotificationTarget::shared_udp(0, destination)` selects the command listener.
If you need a separate source address or port, use
`NotificationTarget::udp()` and configure its endpoint. Check any collector or
firewall rules that depend on the Inform source port.
[Notification target options](../../README.md#choose-a-notification-target)

## Update a custom request transport

Implement `RequestTransport` and use it in trait bounds and imports that used
`Transport`. Accept owned `bytes::Bytes` in `send()` and `request_with()`. When a
complete message arrives, create `ReceivedMessageInfo` with the original message
length and receive time. Pass the original bytes and metadata to the validator
with `ReceivedPacket::new()`. Keep the same absolute registration deadline
across rejected candidates, and remove the registration on completion or
cancellation.
[Custom transport integration example](../../tests/custom_transport.rs)

## Construct manually discovered SNMPv3 engine identities

Replace `v3::parse_discovery_response()` and
`v3::parse_discovery_response_with_limits()` with `v3::DiscoveredEngine::new()`.
After validating the discovery response, pass the engine ID from its decoded
USM security parameters and `msgMaxSize` from its decoded message header.
Use the local transport send capacity when enforcing the encoded request size.
